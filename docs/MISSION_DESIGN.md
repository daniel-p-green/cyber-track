# Mission Design

CyberTrack missions should feel tactical, but the skill being tested is AI operation.

## Mission Types

### Basic Qualification

Purpose: teach the flow.

The player should:

- create a callsign,
- verify local Gemma,
- open a mission in Cursor,
- inspect a small synthetic artifact,
- submit a first result,
- see rank progress.

### Sprint

Purpose: measure speed and disciplined reasoning.

Examples:

- debug a small Python function,
- classify noisy incident logs,
- extract key facts from conflicting reports,
- repair a broken prompt or tool call,
- identify model hallucinations.

### Relay

Purpose: simulate handoffs and future squad play.

Examples:

- player A creates a structured brief,
- player B validates it,
- player C submits a final artifact.

Season Zero can stub this as a solo relay.

### Field Event

Purpose: test narrow technical skills.

Examples:

- local model selection,
- prompt compression,
- evidence ranking,
- synthetic data cleaning,
- notebook repair.

### Marathon

Purpose: test sustained operation under ambiguity.

Examples:

- triage a synthetic incident,
- recover from misleading AI suggestions,
- produce an operations brief,
- validate multiple evidence sources,
- submit a final structured answer.

## Difficulty

Each mission should define:

- expected duration,
- minimum plausible duration,
- maximum score,
- required artifacts,
- validation rubric,
- hint penalties,
- rank requirements,
- model constraints.

## Aesthetic

Use original tactical operations language:

- operation,
- mission,
- squad,
- callsign,
- briefing,
- field model,
- command center,
- after-action report,
- promotion board.

Avoid copied military brands, real unit names, real classified framing, or protected game IP.
